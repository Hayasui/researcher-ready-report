# researcher-ready-report

本仓库是把已经算完的定量读数改写成用户研究员能直接读、直接引用的研究报告的技能。输入是分布表、交叉表与脚本产出，输出是一份按固定骨架组织的备忘录，读者是研究员、产品与运营。

它解决的不是「数字算错了」，而是「数字都对、交付件读起来像工作底稿」。这两种东西的差别集中在十处：结论后置、分母不透明、主语缺失、口径抢占正文、表格过载、术语漂移、事实与解读混排、元话语过多、结构失衡、段落复述表格。判断标准只有一条——一个没参加分析的研究员，能不能在一分钟内知道这份报告的价值，在十分钟内拿到可引用的判断。

## 适用对象

面向定量用研的报告交付，样本来源不限。适用于配额样本、自助平台样本这类分母逐题不同、又需要把口径交代清楚的项目；不适合给机器读的长表（那是数据产物的职责），也不适合问卷、大纲与码表（各有各的源文件）。

技能只管结构与信息分层：先给什么、后给什么，什么进正文、什么下沉。用词与句式交给 `chinese-prose-style`，两份规则冲突时按「用户明确要求 > 事实准确与合规 > 数据与术语准确 > 本技能的结构 > 默认文风」裁决；禁用词、翻译腔、主语缺失、段落盖章这四条语言底线始终归 `chinese-prose-style`，重叠条款的逐条归口在 `references/style-handoff.md`。

## 用法

技能在会话中加载后按骨架执行。触发的话是这几类：「出一份初步研究报告」「把分析结果写成报告」「按议题整理结论」「这份报告读起来像工作底稿」。

交付骨架固定七节，一节都不省：一页摘要（分母表、关键发现 6 至 8 条、未覆盖表）、研究范围、样本与精度、逐议题、数据质量与限制、后续研究的建议、附录。每个议题走同一套五段模板：本议题回答什么、关键结论、关键证据、口径与限制、对后续研究的含义。

三个约定是这份技能的骨架本身。**摘要第一块是分母表**，把全篇用到的几层人一次说清，后面的百分比只写比例与层名，汇报的人不必当场解释分子分母。**叙述里的比例写成「占 X 层的 56.7%」**，主语写出来、选项名写全并加引号，`计数/基数（占比，±ME）` 只留在表格与附录里。**议题内的标题写成结论句**，关键结论挂〔事实〕／〔解读〕标签，让读者一眼看出哪几个数字能进自己的 PPT。

## 定下来的几条原则

**口径下沉。** 分母怎么来的、缺失码怎么处理的、样本是不是概率样本，在研究范围一节与数据质量一节各说一次，正文不再重复提醒。读者不该每读一节就重新处理一遍「这个数能不能比」。

**议题名中性，议题内的标题下判断。** 「议题一　品类基本盘」是目录写法，保留；「认知面宽、转化面窄」是结论写法，用在各级小标题上，让读者扫目录就能抓主线。

**小标题写它要说的事。** 不拿要读者猜的抽象名词当路标，写成「这些数字怎么读」「分母不一样，不能相减」这类句子。

**不造复合简称。** 把动词挤进名词的写法（「主玩款」）要读者在脑子里还原一遍才读得下去，一律写完整短语（「主玩的游戏」）。

**段落不复述表格。** 表里已经有的数字不再用文字念一遍，段落只写表格看不出来的东西：两项之间的落差、和上一节的关系、下一步要验证什么。

**不对称的精度要说明白。** 每个比例带一个误差幅度，并写清它只覆盖随机抽样误差；子群人数少于 100 时只读方向，不读幅度。这句话写在摘要末尾与研究范围一节，正文里出现小样本比较的地方按同一条规则处理。
