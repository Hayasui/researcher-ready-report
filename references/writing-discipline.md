# 报告特有的写作纪律

SKILL.md 第 0 节说了分工，这份文件是那条分工在**落笔**这一层的样子：以下九条里，属于报告独有的在本文件写全，属于语言层的只留指针，去 `chinese-prose-style` 取。写标题、分层、下沉口径、处理术语与元话语、写数字与主语时读它。

## 6.1　标题写成结论

「RO 的存量是三层」是目录写法，「RO 认知高、玩过的人里有一半流失」是结论写法。后者让读者扫标题就能抓主线。议题名保留中性（「议题一　MMORPG 与 RO 的基本盘」），议题内的每一级标题都改成结论。

小标题不用要读者猜的抽象名词（「读法」「口径」「说明」说的不是内容），这一条归 `chinese-prose-style`，判定与改法见它的主规程第 0 节与 `references/banned-words.md`。本技能只补报告里的落法：小标题写成它要说的那件事，例如「这些数字怎么读」「分母不一样，不能相减」。

## 6.2　分层写法

同一件事实，三种写法分别对应三层：

- 事实：《最终幻想14》在在玩组 198 人里占 126 人（63.6%，±6.7pp）。
- 解读：主玩的游戏高度集中，第二梯队只有 7.1%，这批人的 MMORPG 时间是单点投入的。
- 建议验证：若新品要在玩家主玩的游戏上争位置，先要知道他们换主玩的游戏的触发条件，本次问卷没有问。

三者不要塞进同一段。事实进结论条与表，解读进紧跟事实的一句，建议进「对后续研究的含义」。

## 6.3　口径下沉

正文的表注只写这一张表特有的限定（比如「两表分母不同，不可横向比较」）。分母怎么来的、缺失码怎么处理的、样本是不是概率样本，全部在第 1 节与第 6 节说一次，正文不再重复。

## 6.4　术语一物一名

同一批人全篇一个称呼。变量名与题号并排出现一次（术语表里），之后只用中文简称。日文或英文的原始选项保留，首次出现时给一个中文简称，之后用简称。

不要自造把动词挤进名词的简称：「主玩款」要还原成「主玩的游戏」才读得下去，直接写「主玩的游戏」；同类还有「自报款」「抽样款」。这一条归 `chinese-prose-style`（`references/banned-words.md` 里的自造复合简称一节），本技能只在这里留例，不另立规则。

## 6.5　删掉元话语

作者视角的话换成读者视角：

| 删 | 换 |
| --- | --- |
| 需求方给了五个议题，这份处理其中四个 | 本报告覆盖议题一、三、四、五；议题二的口径待定，另出一份 |
| 需求方担心了两件事，数据里排位都不靠前 | 与常见假设的差异：障碍首位是 IP 认知，不是国别 |
| 交付时要一并说明三处缺口 | 未覆盖：Q17、Q28 无数据，Q9 文本未归类 |
| 要写进报告的口径瑕疵 | 数据质量备注 |
| 值得单独记一笔 | 需要留意的口径差异 |

「交付」「需求方」「要写进报告」这类词，除非说的就是交付流程本身，否则一律删。

通用的结构提示语（「先说」「接下来」「还有一点」）不在这张表里，归 `chinese-prose-style` 主规程第 0.4 节，判定是「删掉之后内容一字不少」。

## 6.6　段落不复述表格

表格已经写了数字，段落只写表格看不出来的东西：两项之间的落差、和上一节的关系、下一步要验证什么。一段二到五句。

**复述是在落笔那一刻长出来的，删稿删不干净。** 一段话按表格的行序把读数念一遍，念的时候看不出毛病；等到表格下沉进附录再看，这段话已经是正文里唯一承载那些读数的地方，删无可删。分工因此要在写的时候定：表在正文里承担读数，段落承担判断。

一条判据：把这张表遮住，这段话还剩下什么。剩下排序说明了什么、两组在哪一项上分岔、哪一条推不动，它就立得住；剩下的是「第一位是 X，第二位是 Y」这类行序，那本来就是表的事。

表下沉进附录之后，段落要把结论写全，并指明读数在哪张附录表里，让读者能回去核。**不要把表里的项按行序再念一遍**——念过之后正文里多了一段与附录重复的文字，读者读到的仍是表，只是换了个地方放。

## 6.7　缺口前置并集中

摘要后面挂一张未覆盖表，正文相应位置只留一句「详见第 6 节」。同一个缺口不要在每个议题脚下重复提醒。

## 6.8　数字写法

表格与附录里，比例一律写「计数/基数（占比，±ME）」，例如 `126/198（63.6%，±6.7pp）`。表格列少而宽比多而窄好扫。

叙述里不必重复这一串。摘要与结论写「占 MMORPG 行为层的 38.6%」即可，层名就是分母，分子留在表里；只有当人数本身就是结论时才写人数（「61 人里只有 21 人」）。这样汇报的人只用说百分比与样本数，不用当场解释分子分母怎么算出来的。

分子分母估算过的数（分母换过、分子减过），要在表里单独一行写清两端各是什么，不能只给一个商。一个括号里并排几个百分比时，必须说清哪个对应哪一题（「最不满意」与「退坑原因」各是哪两个数），读者不该靠猜。

**位数按读者定，按上限定不按下限定。** 读者是研究者的备忘录，小数最多两位；读者是业务的报告，一位即可；人数、记录数这类计数一律整数。已交付的研究备忘录里比例写一位（`63.6%`、`±6.7pp`），在这一档之内，新件不必为了凑满两位去改。同一份报告里不许一处两位一处三位，也不许同一列换形态（一张表写 `0.08`、另一张写 `7.87%`；或者一张写分数、另一张写百分比）。例外要写明理由，常见的是 p 值、靠门槛判定的量与按尺度必须多给位的量（log-odds 系数与它的标准误）。

**系数按它自己的尺度转译，换了模型就换说法。** 最小二乘的系数是因变量的单位差；logit 模型的 β 落在 log-odds 上，比值比是它的指数，讲的是几率不是概率，更不能当百分点读。从回归产物出表格与解读时，这一条与它的检查项在 `regression` 技能的 `references/reporting.md` 第 3 节与 `references/tables.md` 第 5 节。

## 6.9　主语不能省

摘要与结论里的判断句，主语一律写出来，比率要说清「谁占谁的多少」。常见的四种毛病：

| 毛病 | 坏例 | 改 |
| --- | --- | --- |
| 主语缺失 | MMORPG 的基本盘是「一半玩过、三分之一还在玩」 | MMORPG 玩家的基本盘是「一半玩过、三分之一还在玩」 |
| 只写比例，不说谁占谁 | 自认 MMORPG 品类的 48.0%，在清单里玩过至少一个的 50.6% | 自认为是 MMORPG 品类玩家的受访者占样本总量的 48.0%，在 17 个清单游戏里玩过至少一个的受访者占 50.6% |
| 题目名缩写，也不加引号 | 最吸引人的体验是故事与世界；最不满意的是课金影响战力 | MMORPG 玩家觉得最吸引人的体验是「故事与世界观」；他们最不满意的是「课金影响战力」和「日常任务占时间」 |
| 主语在句间悄悄换人 | 上一句说玩家，下一句的主语变成问卷或数据 | 一段里的主语固定成玩家或受访者，换主体就写出来 |

日文或英文的原始选项名首次出现时给一次中文简称，之后统一用简称；引用选项名一律加引号，不缩写到读者认不出的程度。

**与 `chinese-prose-style` 的接口。** 通用的主语纪律（同一段连续三句无主语算违规、抽象名词不站句首、一段一个主体）归它，主规程第 0.1 与 3.2 节。表里这四种毛病是报告场景下的具体落法：报告里的判断句必须能被直接引用，谁占谁读不出来就废了。
